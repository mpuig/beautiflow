# Flow

Beautiflow diagrams should communicate one idea clearly before they decorate it.

- Keep one obvious primary path.
- Label every decision branch.
- Keep exceptions secondary but visible.
- Prefer familiar words and short, active labels.
- Preserve semantics when polishing layout.
- Never accept overlaps, arrows through nodes, unreachable nodes, or unreadable text.
- Use color to communicate roles, not decoration.

This file is intentionally prose, not another configuration surface. Beautiflow and its agent skill use the nearest `FLOW.md` as durable context for diagrams below it.
