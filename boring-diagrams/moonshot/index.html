Authoring prompt

The design brief for this example.

Design a fictional modern multi-account telemetry platform. Include device certificate authentication, scoped IoT rules, Kinesis, independent live alarms and buffered archival delivery, cross-account S3/KMS permissions, federated research access and protected central auditing. This is not historical Apollo or safety-critical flight control.

%% @edge devices ingest identity | Device certificates and IoT policies bind each device to allowed telemetry topics.
devices:R --> L:ingest
%% @edge ingest stream event | An IoT rule forwards validated topic traffic using an ingestion role.
ingest:R --> L:stream
%% @edge stream live event | Event-source mapping consumes batches; late and duplicate records require event IDs and timestamps.
stream:R --> L:live
%% @edge live alarms request | Processor publishes custom metrics; configured alarms evaluate the metrics.
live:R --> L:alarms
%% @edge alarms notify event | Alarm transitions notify operators; no flight-control action is implied.
alarms:R --> L:notify
%% @edge stream firehose event | Independent archival consumer buffers delivery without blocking live alarms.
stream:B --> T:firehose
%% @edge firehose raw event | Cross-account S3 writes require delivery-role, bucket and KMS key policies.
firehose:R --> L:raw
%% @edge key raw control | KMS key policy authorizes encryption and separately scoped decryption; this is key association.
key:R --> T:raw
%% @edge analyst athena identity | Federated analysts assume constrained research roles; arbitrary lake access is not granted.
analyst:R --> L:athena
%% @edge athena raw request | Queries use approved datasets and restricted results storage; workgroup and result bucket are omitted.
athena:R --> B:raw
%% @edge ingest trail control | Organization trail captures applicable AWS API activity, not every telemetry payload.
ingest:B --> L:trail
%% @edge trail archive event | Audit retention assumes configured Object Lock, versioning and constrained deletion privileges.
trail:R --> L:archive

Architecture assumptions & omissions
  • Device certificates and topic policies identify publishers. Consumers need timestamps, schema checks and event IDs; neither stream partitioning nor a diagram establishes global event order.
  • Cross-account Firehose delivery needs an execution role, destination bucket policy and KMS permissions. Research access uses scoped roles, approved datasets, workgroups and protected query-result storage; not all these resources are expanded.
  • Protected audit retention assumes S3 versioning, configured Object Lock and appropriately restricted administrators. The organization trail captures applicable AWS API activity, not every sensor payload.
  • Cognito represents federated application sign-in; a backend credential broker or approved federation path must map researchers to scoped AWS query roles. No Cognito-to-Athena direct API call is implied by the identity line. This system is fictional and has no flight-control authority.
